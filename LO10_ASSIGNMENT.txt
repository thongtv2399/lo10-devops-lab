8. IN-MEMORY SERVICE
============================================================

MessageService sử dụng:

ConcurrentHashMap<Long, MessageResponse>

Mục đích:

- Lưu Message trong memory.
- Hỗ trợ nhiều thread truy cập an toàn hơn.
- Không cần Database cho Assignment LO10.

ID được tạo bằng:

AtomicLong

Mục đích:

- Tạo ID tăng tuần tự.
- Hỗ trợ nhiều request đồng thời.
- Tránh race condition khi sinh ID.

Giới hạn:

- Dữ liệu bị mất khi application dừng.
- Không phù hợp để lưu dữ liệu Production.
- Chỉ phục vụ project thực hành LO10.

Docker Build Context là tập hợp file mà Docker Builder
có thể truy cập trong quá trình build.

Khi chạy:

docker build .

Dấu chấm đại diện cho thư mục hiện tại được sử dụng
làm Build Context.

Nếu không giới hạn Build Context, Docker có thể nhận:

- Git history.
- Local build output.
- IDE metadata.
- Log file.
- Temporary file.
- Local environment file.
- Secret file.

Project sử dụng:

.dockerignore

Các nội dung bị loại khỏi Build Context:

- target/
- .git/
- .settings/
- .project
- .classpath
- .idea/
- .vscode/
- File log.
- File temporary.
- .DS_Store.
- .env.
- secrets/.

Lợi ích:

- Giảm kích thước Build Context.
- Tăng tốc Docker Build.
- Giảm nguy cơ đưa file nhạy cảm vào Builder.
- Tránh sử dụng nhầm local build output.

15. GRACEFUL SHUTDOWN
============================================================

Ứng dụng cấu hình:

server.shutdown=graceful

Và:

spring.lifecycle.timeout-per-shutdown-phase=20s

Khi container nhận tín hiệu dừng:

- Application ngừng nhận request mới.
- Request đang xử lý được chờ hoàn tất.
- Application Context được đóng.
- Process kết thúc an toàn.

Graceful Shutdown giúp:

- Giảm request bị ngắt đột ngột.
- Phù hợp môi trường container.
- Phù hợp rolling deployment.
- Tăng độ tin cậy khi scale hoặc restart service.

20. CORRELATION ID
============================================================

Ứng dụng sử dụng Header:

X-Correlation-ID

CorrelationIdFilter extends OncePerRequestFilter.

Mỗi HTTP request đi qua Filter đúng một lần trong
request dispatch thông thường.

------------------------------------------------------------
20.1 Client gửi Correlation ID
------------------------------------------------------------

Request Header:

X-Correlation-ID: lo10-test-001

Application:

- Đọc Header.
- Loại bỏ khoảng trắng.
- Đưa giá trị vào MDC.
- Trả lại cùng giá trị trong Response Header.

Response:

X-Correlation-ID: lo10-test-001

------------------------------------------------------------
20.2 Client không gửi Correlation ID
------------------------------------------------------------

Application tự tạo UUID.

Ví dụ:

4444fe3f-c312-4fbf-b339-262724349b8c

UUID được:

- Đưa vào MDC.
- Gắn vào Response Header.
- Xuất hiện trong Structured JSON Log.

------------------------------------------------------------
20.3 MDC Cleanup
------------------------------------------------------------

Sau khi request hoàn tất:

MDC.remove("correlationId")

Mục đích:

- Tránh Correlation ID bị giữ lại.
- Tránh rò rỉ context giữa các request.
- An toàn khi Web Server tái sử dụng thread.
